1. High-Level Overview

Purpose

LATRICS is a marketing & product showcase website for an industrial intelligence company specialising in autonomous drones, LiDAR mapping, and AI-based analytics for aerospace, energy, and infrastructure sectors.

Problem It Solves

It serves as the company's digital storefront — presenting capabilities, showcasing case studies, displaying live operational telemetry, and capturing leads via a demo request form and newsletter subscription.

3. Component / Module Breakdown

Backend Files

backend/src/index.js — Server Entry Point

  • Role: Bootstraps DB connection, Express app, HTTP server, Socket.IO, graceful shutdown
  • startServer(): Async startup sequence connecting all layers
  • gracefulShutdown(): Handles SIGTERM/SIGINT — clears intervals, closes server

backend/src/app.js — Express App Factory

  • createApp(): Applies CORS, JSON parsing, mounts 3 route groups under /api

backend/src/config/env.js — Environment Helpers

  • getPort(): Parses PORT env, defaults to 5005
  • resolveAllowedOrigins(): Splits CORS_ORIGINS by comma or returns true

backend/src/config/db.js — Database Connection

  • connectDatabase(): Mongoose connection with Google DNS fix for Windows SRV resolution, 5s timeout, non-fatal failure

backend/src/models/Contact.js

  • Mongoose schema: name, email (lowercase), phone, createdAt — all required + trimmed

backend/src/models/Newsletter.js

  • Mongoose schema: email (unique, lowercase), subscribedAt

backend/src/routes/demoRoutes.js

  • POST /api/demo-request: Validates fields → checks DB state → saves Contact → 201/400/503/500

backend/src/routes/liveRoutes.js

  • GET /api/live: Returns simulated telemetry snapshot (fallback for Socket.IO)

backend/src/routes/newsletterRoutes.js

  • POST /api/newsletter-subscribe: Validates email → duplicate check → saves → 201/400/409/500

backend/src/services/liveDataService.js

  • buildLivePayload(): Generates metrics + shuffled activity feed
  • Uses Fisher-Yates shuffle algorithm and random number generation within defined ranges

backend/src/socket/registerLiveSocket.js

  • Emits live:update on connection + every 2500ms; returns shutdown() to clear interval

4. Data Flow Explanation

Example 1: Demo Request Form Submission

1. User fills Name, Email, Phone in DemoForm.jsx
2. Each keystroke -> handleFieldChange() -> setFormData()
3. User clicks "Book demo" -> form onSubmit triggers
4. handleFormSubmit() in useDemoRequest.js:
   a. event.preventDefault()
   b. setIsSubmitting(true)
   c. Calls postDemoRequest(formData)
5. api.js sends: POST /api/demo-request { name, email, phone }
6. demoRoutes.js:
   a. Validates all 3 fields non-empty strings
   b. Checks mongoose.connection.readyState === 1
   c. Creates new Contact, calls .save()
7. Returns 201 { message: "Request received and saved." }
8. api.js returns { ok: true, status: 201, data }
9. Hook sets submitState = { type: "success" }
10. DemoForm renders green success message
11. Form fields reset to empty

Example 2: Live Metrics via WebSocket

1. Backend starts -> registerLiveSocket(io):
   - On connection -> emit("live:update", buildLivePayload())
   - setInterval 2500ms -> io.emit("live:update", payload)
2. buildLivePayload() generates:
   - Timestamp, 4 metrics (random values), 4 shuffled events
3. Frontend socket.io-client is installed but not actively
   connected in current components

Example 3: Newsletter Subscription

1. User enters email in Footer -> setEmail()
2. Clicks subscribe -> handleSubscribe()
3. Calls postNewsletterSubscription(email)
4. POST /api/newsletter-subscribe { email }
5. newsletterRoutes.js:
   a. Validates email contains "@"
   b. Checks for duplicate (findOne)
   c. Saves lowercase -> 201
6. Footer shows success, auto-clears after 5 seconds

5. Key Logic Explanation

Fisher-Yates Shuffle (liveDataService.js)

function fisherYatesShuffle(array) {
  for (let i = array.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [array[i], array[j]] = [array[j], array[i]];
  }
  return array;
}

Why: Produces an unbiased permutation. Each element has equal probability of any position. Used to randomise the activity feed events each broadcast cycle.

rAF-Throttled Scroll (useNavbarScroll.js)

Uses requestAnimationFrame to batch scroll reads into a single frame. Only updates state when the boolean value actually changes — avoids unnecessary React re-renders. Scroll events fire 60+ times/second without throttling.

3D Tilt Effect (Highlights.jsx)

useMotionValue tracks raw mouse position (normalised -0.5 to 0.5) → useSpring smooths values → useTransform maps to rotateX/Y (±5°). Combined with translateZ on child elements for parallax depth.

Procedural Rotor Spin (ProceduralDrone.jsx)

useFrame((state, delta) => ...) runs every animation frame. Increments rotation.y by delta * 15 for frame-rate-independent spinning.

Spring Layout Animation (Industries.jsx)

layoutId="activeIndustry" on the active tab background. Framer Motion auto-animates position between tabs using spring physics.

8. UI/UX Flow

Page Structure (Top to Bottom)

NAVBAR (fixed, scroll-aware blur) --------------------------------- HERO (full-viewport, bg image) --------------------------------- ABOUT (feature card) --------------------------------- SIMULATION (3D interactive drone) --------------------------------- BANNER MARQUEE (partner ticker) --------------------------------- HIGHLIGHTS (scrollable articles) --------------------------------- WHY LATRICS (6-card grid) --------------------------------- INDUSTRIES (tabbed showcase) --------------------------------- CASE STUDIES (4-card grid) --------------------------------- MILESTONES (stats counters) --------------------------------- DEMO FORM (lead capture) --------------------------------- FOOTER (links + newsletter)

Navigation

  • Navbar links use href="#section-id" for in-page anchor scrolling
  • Sections use scroll-mt offset to account for fixed navbar
  • Mobile: hamburger opens animated drawer overlay
  • "Contact Us" CTA scrolls to #contact (DemoForm)

State Management

No global store (Redux/Zustand). All state is local React useState/useEffect: scroll state, active industry tab, form data, mobile menu toggle, newsletter form.

11. Performance & Optimization

Current

  • rAF scroll throttling in useNavbarScroll
  • Conditional state updates (only when value changes)
  • React.memo on MilestoneCard
  • viewport: { once: true } — animations fire only once
  • 3D scene inside <Suspense> for non-blocking load
  • Tailwind v4 — zero-runtime CSS
  • Google Fonts preconnect headers

Suggested Improvements

  • Image optimization: hero_bg.png is 32MB — compress and convert to WebP
  • Code splitting: Lazy-load 3D scene with React.lazy()
  • Remove unused socket.io-client: Reduces bundle size
  • Font subsetting: Load only needed Poppins weights
  • Service Worker: Add for offline static asset caching

12. Security Considerations

Current Measures

  • CORS whitelist from environment variables
  • Server-side input validation + trimming
  • Email normalisation (lowercase storage)
  • MongoDB URI only in backend .env
  • Unique index on newsletter email prevents duplicates

Areas of Concern

Warning:
  • MongoDB URI with credentials in .env file — should be in .gitignore and credentials rotated
  • No rate limiting on API endpoints (spam/brute-force vulnerable)
  • Email validation only checks for "@" (not RFC 5322)
  • No CSRF protection (relies solely on CORS)
  • No HTTPS enforcement for production
  • All API endpoints are unauthenticated

14. Summary for Client KT (Non-Technical)

What is LATRICS?

Think of it as a company's interactive brochure website — but much more advanced than a static page. It's like visiting a car dealership's website where you can:

  • See a 3D model of the product (drone) that you can rotate and zoom
  • Watch live operational stats updating in real-time
  • Fill out a "Request Demo" form to get in touch with sales
  • Subscribe to a newsletter for updates

How Does It Work?

Imagine a restaurant:

  • The dining room (Frontend) is what customers see — the beautiful UI
  • The kitchen (Backend) is behind the scenes — receives orders, stores them
  • The intercom (WebSocket) lets the kitchen send real-time updates without anyone walking back and forth

Key Takeaways

  1. It's a single-page application — loads once, never refreshes
  2. The backend has only 3 API endpoints — lightweight by design
  3. Live metrics are simulated (random numbers within realistic ranges)
  4. Form data is persisted to a cloud database (MongoDB Atlas)
  5. The codebase is well-structured with clear separation of concerns
